## 2. Il prodotto

Applicazione multi-cliente che interroga le AI via API, analizza le risposte e produce metriche +
piano d'azione. Innestata su Ainstein.

### Architettura concordata (7 blocchi)

1. **Multi-tenant** — un record per cliente TD, stesso motore per tutti.
2. **Prompt engine** — un LLM genera per ogni cliente ~40-60 prompt in 4 cluster, IT+EN, con
   varianti di persona (investitore, giornalista, cliente arrabbiato):
   navigazionali ("chi è X") · reputazionali ("X recensioni / problemi / affidabile?", cuore per
   TD) · commerciali ("migliori advisor immobiliare alberghiero lusso Italia") · comparativi
   ("X vs competitor").
3. **Collector via API** (risposte reali con fonti): OpenAI Responses API + `web_search` ·
   Perplexity Sonar (citations native) · Gemini API con Google Search grounding
   (`groundingMetadata`) · Anthropic Claude con web search · (fase 2) Google AI Overviews via SERP
   API. Ogni prompt × engine × 3 run → score di stabilità.
4. **Analyzer** = LLM-as-judge (JSON strutturato): brand citato sì/no, posizione, sentiment, claim
   estratti vs "verità del brand" (fact-check allucinazioni), competitor nominati, fonti citate per
   dominio, flag contenuto negativo + URL sorgente.
5. **Metriche/dashboard**: AI Share of Voice · Citation Share per dominio · Sentiment Index ·
   Reputation Risk Score · Source Map (domini di cui le AI "si fidano").
6. **Piano d'azione automatico**: fonte negativa → target rimozione; gap → proposta articolo + testata.
7. **Run schedulato + diff**: settimanale, confronto con run precedente, alert (WhatsApp/email) su
   nuova menzione negativa o nuova fonte. Report PDF white-label mensile.

**Fase 3 (futuristico)**: grafo di influenza fonti→risposte; simulazione "se pubblico su X cosa
cambia"; rilancio automatico dei prompt dopo ogni pubblicazione per misurare l'effetto.

**Costi API**: stimati in pochi euro/settimana per cliente (listini da verificare prima della proposta).

### Step 1 ridefinito — Onboarding automatico (decisione chiave)

Clemente ha bocciato i form con molti campi:
- **Input unico: il nome** (azienda o persona). Opzionale sito/città solo se ambiguo.
- Un agente di onboarding fa ricerca web + interroga le AI ("chi è X") e compila una **bozza di
  profilo**: identità, attività, varianti del nome, persone collegate, fatti chiave, temi di rischio
  rilevati online, omonimi da escludere, fonti che lo citano.
- L'utente conferma riga per riga: ✅ vero · ❌ falso/non è lui · ✏️ correggi. Solo i confermati
  diventano "verità del brand"; i ❌ diventano automaticamente errori da monitorare.
- **Competitor = output, non input**: emergono dal monitoraggio. Aggiungibili a mano dopo.
- Campi obbligatori a mano: **zero**.
